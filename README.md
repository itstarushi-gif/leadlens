# LeadLens: AI-Powered Lead Scoring and Sales Recommendation System for Salesforce

**[>> Try the live demo](https://itstarushi-gif.github.io/leadlens/)** - the full SDR Workbench with the trained model and sample leads running entirely in your browser (no server needed).

An AI assistant for SDRs. A lead enters Salesforce, the model predicts its chance of converting, a 0-100 score ranks it,
and a Next Best Action with a plain-English reason is written back onto the Lead record.

```
Lead enters Salesforce -> features built -> ML predicts conversion probability -> Lead Score 0-100
 -> priority ranking -> Next Best Action + reason -> SDR acts -> outcome logged (feedback for retraining)
```

## What is in here
| Folder | What it does |
|---|---|
| `src/generate_data.py` | Synthetic Salesforce Lead data (6,000 leads, 33% converted) with hidden buyer interest + noise |
| `src/features.py` | Raw Lead fields -> 27 model features |
| `src/train.py` | Trains logistic regression (baseline) and gradient boosting, evaluates, exports `models/model.json`, writes `reports/` |
| `src/model_io.py` | Pure-JSON model scoring + per-feature explanation (path attribution; contributions add up exactly to the log-odds) |
| `src/recommend.py` | Score -> Priority, Next Best Action, Recommendation Reason |
| `src/crm.py` | CRM layer: real Salesforce (simple-salesforce) if `SF_*` env vars are set, else `data/crm_leads.csv` is a mock CRM |
| `api/main.py` | FastAPI service: `/score`, `/score/batch`, `/api/leads`, `/api/rescore`, `/api/outcome`; SDR Workbench at `/` |
| `web/workbench.html` | SDR Workbench UI (ranked leads, AI panel, why-this-score, what-if rescoring, outcome logging, model results) |
| `salesforce/` | Salesforce DX project: 19 custom Lead fields, Apex `LeadScoringService`, `LeadAiTrigger`, LWC `leadAiPanel`, Named Credential |
| `tests/` | Unit tests, API tests and a JS-vs-Python parity test |

## Run it
```bash
pip install -r requirements.txt
python -m src.generate_data        # creates data/leads_history.csv
python -m src.train                # trains, evaluates, writes models/model.json and reports/
python -m scripts.score_crm        # scores every open lead in the CRM and writes AI fields back
uvicorn api.main:app --reload      # open http://127.0.0.1:8000 (SDR Workbench) and /docs (API)
python -m tests.test_all           # all tests
python -m scripts.build_standalone # one-file demo -> dist/leadlens_workbench.html
```

## Results (held-out test set, 1,800 leads)
| Model | AUC | Precision top 20% | Lift |
|---|---|---|---|
| Logistic regression (baseline) | 0.876 | 84.2% | 2.52x |
| Gradient boosting (production) | 0.871 | 82.2% | 2.46x |

| Priority tier | Leads | Actually converted |
|---|---|---|
| Very High (90-100) | 115 | 95.7% |
| High (75-89) | 124 | 87.9% |
| Medium (50-74) | 256 | 61.3% |
| Low (0-49) | 1,305 | 17.2% |

Working only the top 20% of leads captures about half of all conversions. The data is synthetic and generated by a
logistic process, so the simple baseline matches the boosted model; with real CRM data gradient boosting usually wins.
State this openly in your report.

## Priority and Next Best Action rules
| Score | Priority | Next Best Action |
|---|---|---|
| 90-100 | Very High | Call the lead (falls back to personalized email if no phone on file) |
| 80-89 | High | Schedule a demo |
| 70-79 | High (75+) or Medium | Send personalized email |
| 50-69 | Medium | Follow up later |
| 0-49 | Low | Put into nurture |

## Connect to a real Salesforce org
1. Create a free Developer Edition org at developer.salesforce.com/signup.
2. Deploy the metadata: `sf project deploy start -d salesforce/force-app` (adds 19 Lead fields, Apex, trigger, LWC).
3. Host this API on a public HTTPS URL (Render, Railway, Azure...), then put that URL in
   `salesforce/force-app/main/default/namedCredentials/LeadLens_API.namedCredential-meta.xml` and redeploy.
4. Load sample leads: set `SF_USERNAME`, `SF_PASSWORD`, `SF_TOKEN` (and `SF_DOMAIN=test` for sandboxes), then
   `python -m scripts.load_to_salesforce 500`.
5. Score them: `python -m scripts.score_crm` (batch), or create/update a Lead and the trigger calls the API.
6. In Lightning App Builder, add the **leadAiPanel** component to the Lead record page, and add list-view columns for
   AI Lead Score, AI Priority and Next Best Action.
7. Optional: a Flow using the invocable action "Score Lead with LeadLens", and a dashboard on `AI_Priority__c`.

Note: the Salesforce metadata and Apex follow the Salesforce DX format but were not deployed to a live org while building
this, so test in your Developer org first and adjust names if needed. The Python side, API and workbench are tested.

## Feedback loop
Every outcome an SDR logs goes to `data/outcomes.csv` (or a Task in Salesforce). Add those results to
`data/leads_history.csv`, run `python -m src.train` again, and the model learns from real outcomes.
